### 1.2 P 核和 E 核对比

| 核心类型 | 数量 | 基础频率 | 最大睿频 | 特点 |
|---------|------|---------|---------|------|
| **P核** | 4 | 2.1 GHz | **4.6 GHz** | 大核心，性能强劲，适合单线程和重负载 |
| **E核** | 4 | 1.5 GHz | **3.4 GHz** | 小核心，功耗低，适合多线程和轻负载 |

### 1.3 如何确认最大睿频？

> **重要提示**：在 WSL2 环境中，大部分 Linux 工具（如 `cpupower`、`turbostat`、`cpufreq` 接口）无法使用。Windows 的 `Win32_Processor` API 也只返回基础频率，不返回最大睿频。

#### 推荐方法：使用 CPU-Z（最准确）

**下载地址**：https://www.cpuid.com/downloads/cpu-z/cpu-z_2.20.2-cn.exe

**使用方法**：
1. 在 Windows 中运行 CPU-Z
2. 查看 **处理器** 标签页
3. 找到 **倍频** 字段，格式为 `xN.N (min-max)`
4. **最大睿频 = 最大倍频 × 总线速度**

**示例**（来自截图 [1CPU.png](file:///home/hill/gemm/doc/CPU-Z/1CPU.png)）：
```
倍频:      x11.0 (4.0-46.0)
总线速度:  99.76 MHz

最大睿频 = 46.0 × 100 MHz = 4.6 GHz
```

#### 其他方法

| 方法 | 是否能看到最大睿频 | 说明 |
|------|------------------|------|
| CPU-Z | ✅ | 查看倍频范围，计算得出 |
| Intel ARK | ✅ | 官方权威来源 |
| 任务管理器 | ⚠️ | 部分版本显示"最大频率"字段 |
| Win32_Processor | ❌ | 只返回基础频率 |
| Linux cpufreq | ❌ | WSL2 中不可用 |

详细说明请参考 [CPU-Z 说明文档](file:///home/hill/gemm/doc/CPU-Z/说明.md)。

### 1.4 逻辑 CPU 到物理核心的映射

| 逻辑 CPU | 物理核心 | 核心类型 |
|---------|---------|---------|
| CPU 0-1 | Core 0 | P核 |
| CPU 2-3 | Core 1 | P核 |
| CPU 4-5 | Core 2 | P核 |
| CPU 6-7 | Core 3 | P核 |
| CPU 8-9 | Core 4 | E核 |
| CPU 10-11 | Core 5 | E核 |

### 1.5 如何确保程序在 P 核上运行？

```bash
# 将进程绑定到 P 核（CPU 0-7）
taskset -c 0-7 ./MMult_4x4_15.x

# 查看进程运行在哪个 CPU 上
ps -eo pid,args,psr
taskset -cp [PID]
```

## 三、常见问题

### 3.1 为什么 WSL2 中看不到最大睿频？

WSL2 运行在 Windows 虚拟机中，部分硬件信息被虚拟化层隔离，导致：
- `cpufreq` 子系统不可用
- `intel_pstate` 驱动不可用
- `lscpu` 不显示 `CPU max MHz` 字段

### 3.2 如何验证睿频是否生效？

1. 使用 CPU-Z 查看倍频范围
2. 运行计算密集型任务时，观察 CPU-Z 的"核心速度"是否超过基础频率
3. 确保 BIOS 中启用了 `Intel Turbo Boost Technology`
